Prompt

I want to develop a real-time secure chat application similar to WhatsApp with both frontend and backend. The system must ensure end-to-end security and also provide a smooth user experience. Below are the exact requirements:

Core Objectives

Ensure confidentiality of messages using AES symmetric encryption.

Implement RSA asymmetric encryption for secure key exchange.

Use SHA (SHA-256) hashing for message integrity and authentication.

Demonstrate communication security using Wireshark (packet analysis) and Nmap (port scanning).

Provide a user-friendly frontend with presence, typing bubbles, and delivery/read status.

Functional Requirements

User Authentication

Signup/login system with securely stored salted+hashed passwords.

Users should appear as "online" when logged in.

Key Management & Exchange

Each user generates an RSA key pair.

Public keys are exchanged via the server.

AES session keys are generated per chat session and encrypted with RSA for secure delivery.

Secure Messaging

All messages are encrypted using AES (AES-256-GCM preferred) before leaving the sender’s device.

Messages are decrypted only at the receiver’s device.

Server should relay only encrypted blobs (no plaintext).

Integrity & Authentication

Each message must carry a SHA-256 hash (or HMAC-SHA256).

Receiver verifies hash to confirm integrity and sender authenticity.

Real-time Features

Show active/last seen status.

Show typing indicator when the other user is typing.

Show delivery/read ticks (✔ sent, ✔✔ delivered, ✔✔ blue = read).

Messages should update instantly on both users’ interfaces.

Network Security Demonstration

Use Wireshark to capture traffic and show that the actual message payload is encrypted (ciphertext only).

Use Nmap to scan the server, detect open ports, and report findings.

Non-Functional & Security Constraints

Private keys (RSA) must remain only on the client’s device.

AES session keys must never be transmitted in plaintext.

Do not use insecure ciphers like DES/MD5 for core functionality (only for learning demos if needed).

Consider replay and MITM attacks — include simple defenses.

Ensure communication happens over TLS (WSS/HTTPS) in addition to message-level encryption.

Tech Stack

Frontend: React.js or plain HTML/CSS/JS with WebSocket (Socket.IO) for real-time events.

Backend: [Node.js (Express + Socket.IO) or Python (FastAPI + websockets).] choose which is easy to implement

Crypto Libraries:

WebCrypto API (browser)

crypto (Node.js) or PyCryptodome (Python) [choose which is easy to implement]

Database: JSON for user accounts & public key storage.

Deliverables

Source code for frontend and backend (with setup instructions).

README explaining architecture, crypto workflow (AES+RSA+SHA), and how to run the project step by step.

explain how to work in wireshark and nmap
